1. Метод [POST] /api-v2/projects (Создание проекта)
Позитивный тест (test_create_project_positive):
Суть: Проверяет, что при передаче валидного JSON с уникальным заголовком (title), сервер возвращает статус 201 Created.
Проверка: Убеждаемся, что в теле ответа присутствует поле id созданного проекта.
Негативный тест (test_create_project_negative_no_title):
Суть: Проверяет реакцию API на отсутствие обязательного поля title.
Проверка: Ожидаем код ошибки клиента 400 Bad Request или аналогичный (согласно документации Yougile).
2. Метод [GET] /api-v2/projects/{id} (Получение проекта)
Позитивный тест (test_get_project_positive):
Суть: Проверяет получение данных реально существующего проекта.
Проверка: Сначала создаем проект, берем его id, запрашиваем данные и сверяем, что полученный id совпадает с запрошенным. Статус 200 OK.
Негативный тест (test_get_project_negative_not_found):
Суть: Проверяет запрос данных по несуществующему или случайному ID.
Проверка: Ожидаем статус 404 Not Found.
3. Метод [PUT] /api-v2/projects/{id} (Обновление проекта)
Позитивный тест (test_update_project_positive):
Суть: Проверяет возможность изменения названия проекта.
Проверка: Создаем проект, отправляем запрос на изменение title. Проверяем статус 200 OK и затем делаем контрольный GET запрос, чтобы убедиться, что название действительно обновилось.
Негативный тест (test_update_project_negative_invalid_id):
Суть: Попытка обновить проект с некорректным форматом ID (например, строка "invalid-id").
Проверка: Ожидаем код ошибки 400 или 404, что подтверждает невозможность операции с невалидным идентификатором.
